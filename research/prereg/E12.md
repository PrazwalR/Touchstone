# E12 pre-registration draft · Quote integrity

Status: **draft**. No sampled fork run or E12 verdict.

The experiment is a fork test under developer spec §16.4. Keep the original rules: any same-state
deposit/quote mismatch blocks release; `depositIfFlagged` must bound the next-block deposit on at least
99% of the registered samples. The existing local fuzz suites are engineering evidence, not this experiment.

## Required observations

Use the owner's post-M10 deployments on Arbitrum Sepolia and Base Sepolia. Pin chain IDs, deployment
transactions, deployed runtime hashes, constructor settings, pool keys, oracle feeds and the V4Quoter
identity. Require archive state and exact transaction ordering. Reject old deployments without the lens.

For each sampled swap, record block/transaction/log identities, exactness, direction, amount, price limit,
caller and hookData. Reconstruct the pre-transaction state, including earlier transactions in its block.
Measure `previewDeposit` using the gross quote notional and convert a risky-token deposit using the
executed gross receipts, as the contract does. Compare both amounts and flagged state.

Compare the indicative quote with V4Quoter from the same state. Register how licence-holder conservatism,
partial fills and the quote's tick/empty-word budget are categorized. Budget-exhausted zero quotes must be
reported separately from successful comparisons and never counted as matches. Register the one-wei
tolerance from §17.2 explicitly, alongside §16.4's mismatch rule, before freezing.

For the next-block check, take the preview from the preceding registered state and compare with actual
deposit execution in the following block. Keep notional and currency units explicit. Include intervening
swaps, reference updates, calendar transitions, licence changes and outstanding-cap occupancy. Do not
discard failures caused by changed state: the 99% line is an empirical requirement. The current-rate
`depositIfFlagged` is not an unconditional bound on future reference prices or trade notional.

## Freeze checklist

Register development/held-out block windows, sample selection, minimum coverage per chain, missing-state
policy, deterministic seed if sampling, and all comparison categories before accessing the sampled tape.
Commit the tested reconstruction and scoring code, then separately commit its hash, this registration and
the freeze ledger. Record every input hash and every mismatch in the results. No deployment addresses,
sample counts or successful outcomes are invented here.
