# Frontend

The Touchstone site: the cinematic explainer from `design/` (instrument system v1), plus live, read-only state
from the selected testnet deployment and a wallet-connected guarded swap page. Vite, React 19 and strict TypeScript, with viem for reads and zod
for every input.

## Run it

```sh
cd frontend
pnpm install
pnpm dev            # http://localhost:5173
pnpm test           # math against research/reference, deployment schema, code excerpts against contracts/src
pnpm build          # typecheck, then a static site in dist/
pnpm preview        # serve dist/
```

`VITE_CHAIN` selects a synced deployment. It defaults to `arbitrum-sepolia`. After the owner deploys on Base Sepolia and runs `pnpm sync`, use `VITE_CHAIN=base-sepolia`. The build rejects a missing deployment. Leave `VITE_RPC_URL` unset to use that deployment's public RPC. All `VITE_` settings ship in the public bundle.

Choose **Exact input** to set the payment or **Exact output** to request a quantity of the receiving token. In exact-output mode the deposit is in the payment token. The wallet approves at most the displayed input cap. Native-currency swaps send that cap and the router refunds unused value. The quote and pre-sign simulation check the requested output. At execution the router enforces the payment and deposit caps, so liquidity exhaustion can still cause a partial fill.

## What the page is

| Act | Section | Data |
| --- | --- | --- |
| Hero | Interactive stone; the pointer draws a mark | Illustration |
| I to III | Scroll theatre of one record, or three still frames under reduced motion | Worked example (research report) |
| IV | Four markets: clawback, licence, rebates, quote integrity | Worked example; status chips per facet |
| V | Closed markets, with a draggable reopening | Illustration, plus the deployed NYSE calendar read live |
| VI | Settlement laboratory | BigInt port of DepositLib and SettlementMath; can load the deployed pool's parameters |
| VII | Architecture pipeline, eight states with code excerpts | Verbatim lines of `contracts/src`, tested |
| VIII | Testnet: pool, hook, config, a `previewDeposit` quote, record history, contract table | Measured, from Arbitrum Sepolia |
| IX | Status: implemented, specified, not done | Measured test counts with a date |

Every number carries its label (spec §0.8): worked example, illustrative, simulation, or measured.

## Keeping it current

After a contract change or a new deployment, from the repository root:

```sh
(cd contracts && forge build)
node frontend/scripts/sync-contracts.mjs
(cd frontend && pnpm test)
```

The sync copies ABIs from `contracts/out/`, and addresses, chain metadata and the deploy block from
`contracts/deployments/<chain>.json`, `contracts/script/config/<chain>.json` and the DeployCore broadcast.
`test/excerpts.test.ts` fails when a contract line quoted on the page no longer exists in the source, and
`test/deployment.test.ts` fails when the page's addresses differ from the contracts workspace.

## Security

- Read-only. There is no wallet connection, no signing and no transaction; every chain call is `eth_call` or
  `eth_getLogs` (spec §0.7).
- The production build carries a Content-Security-Policy that allows scripts from the page's own origin, fonts
  from Google, and connections to the one RPC origin. HSTS, `X-Content-Type-Options: nosniff`, `Referrer-Policy`
  and `frame-ancestors 'none'` cannot be set from HTML; set them as response headers on the host.
- RPC responses are decoded against the ABIs, and the chain id is checked before the first read. The deployment
  file is validated with a strict schema that rejects unknown fields.

## Interface system

The existing Vite app uses shadcn/ui preset `beEjvrZg` (Base UI Luma, zinc, berry primary, Geist, pointer cursors), initialized with `pnpm dlx shadcn@latest init --preset beEjvrZg --template next --pointer`. The CLI detects the existing Vite project; it does not scaffold Next.js. Tailwind v4 is registered in `vite.config.ts`, and `components.json` points new components to `src/components/ui`.

`src/styles/globals.css` contains the generated preset. `src/styles/refined.css` adapts the existing instrument layouts with Manrope headings, quieter copy and the original gold settlement visuals. The custom stone engine uses a satin graphite material with larger screen-space annotations. Shader resolution adapts independently so labels stay sharp. Portrait framing keeps the allocation destinations in view; the scene sequence, timing and settlement arithmetic are preserved. Use the shadcn primitives for controls and `ActionLink` for button links.

Swap and Simulation use the shared presentation layout in `src/components/DemoLayout.tsx` and `src/styles/demo.css`: trade amounts, deposit and guards stay visible beside a live settlement receipt. Trade settings, full allocation, pool configuration and indexed history remain available through disclosures. Simulation refreshes live prices without remounting an edited or pending trade.

The Swap pool inspector separates market facts, token balances and configuration into tabs. Configuration uses individual plain-language labels, with explicit units for every rate and time window.
